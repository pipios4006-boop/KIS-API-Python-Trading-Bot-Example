📈 핵심 퀀트 공식 및 타점 락온 (V14 & V-REV & AVWAP)
봇의 모든 매수/매도 타점 연산 시 아래 공식을 100% 팩트로 적용하라.
💎 오리지널 무한매수법 (V14) 핵심 공식
🔹 1회 예산 : Portion = Seed / Split
🔹 T값 (절대 진행률) : T = (Total Holdings * Average Price) / Portion
🔹 목표 익절가 : Target = Average Price * (1 + Target Ratio)
🔹 별값 (Star Price) 연산 :
🔸 감가상각 계수 : DF = 2 / Split (Split이 0이면 0.1 적용)
🔸 별% : Star Ratio = Target Ratio - (Target Ratio * DF * T)
🔸 별값 : Star Price = Average Price * (1 + Star Ratio)
🔹 매수 타점 (0주) : Buy_1, Buy_2 = MAX(0.01, PrevClose * 1.15 - 0.01) (예산 50%씩)
🔹 매수 타점 (전반전, T < Split / 2) :
🔸 평단 매수 : Buy_Avg = MIN(Average Price, Star Price) - 0.01 (예산 50%)
🔸 별값 매수 : Buy_Star = Star Price - 0.01 (예산 50%)
🔹 매수 타점 (후반전, T >= Split / 2) :
🔸 통합 별값 매수 : Buy_Star = Star Price - 0.01 (예산 100% 단일 버킷 통합)
🔹 보너스 덫 (심해 줍줍, Jubjub) :
🔸 발동 조건 : 기본 매수 주문 수량(Q_Base)이 1주 이상일 때
🔸 타점 역산 : Jub_Price = ROUNDDOWN(1회 예산 / (Q_Base + n), 2) (n은 1부터 5까지)
🔸 장전 방식 : 산출된 Jub_Price가 $0.01 초과 시, 각각 1주씩 총 5개의 덫을 '예약주문'이 아닌 '해외주식 본주문(Regular Order)' API를 사용하여 LOC(시장가 온 클로즈) 조건으로 강제 장전한다.
🔹 매도 타점 :
🔸 쿼터 익절 : 보유 수량의 25% (ROUNDUP(Qty / 4)) 물량을 Star Price에 매도
🔸 목표 익절 : 잔여 수량을 Target Price에 매도
🔹 ♻️ V14 서브 로직 리버스 모드 (소진 방어 및 복구 엔진) 핵심 공식
🔸 발동 조건 및 자금 통제 : T > Split - 1 (20분할은 T > 19, 40분할은 T > 39) 돌파 시 즉시 전환. 남은 잔금은 리버스 모드 예산으로 100% 이관되며, 원금(Seed) 추가 투입(Zero-Injection)은 시스템 전역에서 영구 차단한다.
🔸 리버스 별값 (Rev_Star) 연산 : 직전 5거래일 종가의 산술 평균(SMA 5). (1일 차 매도 시에는 미적용).
🔸 1일 차 (소진 당일) 타격 방식 : 쿼터 매수 전면 차단. 무조건 매도(MOC) 방식으로 타격하며, 매도 수량은 전체 보유 개수의 N등분 (20분할 = 10등분 / 40분할 = 20등분, 소수점 이하 내림 강제).
🔸 2일 차 이후 타격 방식 (종료 시까지 무한 반복) : 총 잔금(이월 잔금 + 매도 대금) / 4 만큼의 예산을 Rev_Star(별지점) 아래에서 매수 시도. 직전 보유 개수의 N등분(20분할 = 10등분 / 40분할 = 20등분, 내림 적용) 수량을 Rev_Star(별지점) 위에서 매도 시도.
🔸 T값 동적 스케일링 연산 : 20분할 무매는 매도 시 T = 직전 T * 0.9, 매수 시 T = 직전 T + (20 - 직전 T) * 0.25 / 40분할 무매는 매도 시 T = 직전 T * 0.95, 매수 시 T = 직전 T + (40 - 직전 T) * 0.25.
🔸 탈출 및 일반 모드(V14) 복귀 조건 : 당일 종가가 보유 평단 대비 TQQQ는 -15% 보다 커지고(회복), SOXL은 -20% 보다 커지는 것을 확인하면 리버스 모드를 즉시 종료. 리버스 모드에서 연산된 최종 T값을 그대로 상속받아 일반 모드로 복귀. 복귀 후 1회 매수금(Portion)은 '현시점 총 잔금 / (Split - T)' 공식으로 타점 재조정. 일반 모드 복귀 후 잔여 예산이 1회 매수분 미만으로 다시 소진될 경우 즉각 리버스 모드로 재돌입.
⚖️ 역추세 하이브리드 (Reversion, V-REV) 핵심 공식
🔹 큐(Queue) 장부 종속성 락온 : 큐 장부는 오직 V-REV(역추세) 모드 전용 아키텍처이다. 절대로 오리지널 모드(V14 LOC, V14 VWAP) 연산 시에는 큐 장부가 개입하지 않도록 시스템 전역에서 100% 격리(Bypass)하라.
🔹 2-Tier Auto-Merge Protocol (지층 병합) : 큐 장부에 3개 이상의 지층이 발생할 경우, 1층(가장 최근 매수 지층)을 제외한 2층과 3층(모든 과거 상위 지층)을 즉각 하나의 지층으로 원자적 가중 평균(Weighted Average) 병합하여 최대 2개 지층(2-Bucket) 체제를 강제한다.
🔹 1일 고정 예산 및 정량제 산출 : 당일 1회분 예산은 '총 시드(Total Seed) * 0.15'로 고정(정액제)한다. 당일 스냅샷 지시서 생성 시 이 고정 예산을 타점(PrevClose 등)으로 나누어 당일 매수할 '목표 수량(정량)'을 산출하고 영구 고정한다. 하락장으로 인해 정량 매수 후 예산이 남더라도 억지로 추가 매수하지 않으며, 절약된 잔액은 총 시드 풀에 보존되어 전체 매수 가능 횟수(Runway)를 7회 이상으로 극적으로 늘려 시드 고갈을 방어한다.
🔹 정액제 기반 정량제 1층 절대 사수 및 지층 무결성 4대 방정식 : 반쪽짜리 매수(부분 체결)나 다중 지층 병합(하향식 흡수/상향식 이관) 발생 시, 1층(최근 매수)의 평단가 오염과 총 평단가의 훼손을 원천 차단하기 위해 아래 4대 수학적 무결성을 100% 팩트로 적용한다.
🔸 1. 정량제 수량 락온 : 1층 수량은 산출된 '당일 목표 정량(Fixed-Quantity)'으로 절대 고정한다.
🔸 2. 당일 평단가 보존 : 1층 평단가는 상위층과 절대 섞지 않고 '당일 체결 단가'를 100% 순수하게 유지한다.
🔸 3. 상위층(2층) 수량 재배치 : 보유한 전체 총 수량에서 1층 정량을 뺀 나머지만 상위층 수량으로 배정한다.
🔸 4. 총 평단가 오염 차단 (역산 엔진) : '기존 전체 총 투자금(Total Invested)'에서 '새로운 1층 투자금'을 뺀 잔액을 상위층 수량으로 나누어 상위층 평단가를 역산한다. 이로써 단 1센트의 오차도 없이 총 평단가를 100% 보존한다. 단, 역산된 상위층 단가는 '기존 총 평단가'를 절대 초과할 수 없도록 강제 하드 캡핑(Hard Capping)하여 풍선 효과(Balloon Effect)를 차단한다.
🔹 매수 앵커 및 타점 :
🔸 0주 새출발 : Buy_1 = PrevClose * 1.15, Buy_2 = PrevClose * 0.999
🔸 기보유 상태 (L1_Price 앵커 락온) : Anchor = L1_Price, Buy_1 = Anchor * 0.998, Buy_2 = Anchor * 0.993
🔹 당일 졸업 후 새 사이클 강제 재진입 (Same-Day Re-entry) : 프리장 개장(04:00 EST)부터 정규장 마감 45분 전(15:15 EST) 사이에 전량 익절(졸업)이 발생하여 잔고가 0주가 될 경우, 1회분 1일 고정 예산(15%)을 투입하여 당일 정규장 종가(LOC) 매수 주문을 장전하여 새로운 사이클 시작한다.
🔹 매도 타점 (LIFO 단일/다중 지층 분기 탈출) :
🔸 단일 지층 (1개 층 보유) : 상위층 덫 소각, 오직 1층 탈출망(Sell_L1 = L1_Price * 1.006) 단독 장전
🔸 다중 지층 (2개 층 이상 보유) : 1층 탈출망(Sell_L1 = L1_Price * 1.006) 및 상위층 통합 탈출망(Sell_Upper = Upper_Price * 1.010) 동시 장전
🔹 자전거래 방어막 캡핑 : MinSell = MIN(Sell_L1, Sell_Upper). 매수 타점이 MinSell 이상이면 MAX(0.01, MinSell - 0.01)로 하향 조정. (단일 지층일 경우 MinSell = Sell_L1)
🔹 평단가 리앵커링 (수익금 단가 차감 & KIS 원장 100% 디커플링) :
🔸 KIS 증권사 평단가(AVWAP 오염)를 절대 참조하지 않고 오직 순수 로컬 큐(Queue) 장부만 신뢰한다.
🔸 하위 지층 단가 상승 패러독스 원천 차단 : 1층 익절 후 잔여 지층이 2개 이상일 때는 개별 평단가를 100% 보존한다.
🔸 단일 지층 마법 격발 : 오직 잔여 지층이 단 1개 남았을 때만(len(q) == 1), 회수된 현금을 투입하여 잔여 악성 지층의 매수가를 하향 재조정한다 : New_Price = MAX(0.01, (Pure_Total_Invested - Net_Realized_Cash) / Remaining_Qty). 단, Net_Realized_Cash는 왕복 수수료 및 슬리피지 버퍼 0.6%를 선차감한 순수 회수금(Realized_Cash * 0.994)이다.
🔸 단일 지층 초과분 정밀 분할(Tier Split) 및 단가 역전 방어 : 단일 지층 마법 격발 시, 해당 지층의 총 투자금이 1회분 예산을 초과(10% 버퍼)할 경우 예산 팽창 패러독스를 막기 위해 정규장 종가(PrevClose)를 기준으로 1회분 예산만큼 1층으로 분할하고 잔여분을 2층으로 역산 분리(Split)한다. 단, 지층 단가 역전(Price Inversion) 패러독스를 원천 차단하기 위해 전체 평단가가 정규장 종가보다 높을 때(new_pure_price > prev_close)만 분할을 100% 허용한다.
🔹 자체 VWAP 1분 슬라이싱 엔진 (가중치 기반 분할 타격) :
🔸 타임라인 : 15:27 EST ~ 15:57:59 EST (30분 타격 + 1분 클린업 가동)
🔸 가중치 분배 : 5개년 누적 거래량 프로파일(VWAP_PROFILES) 기반 매 1분 단위 타겟 수량 할당.
🔸 타격 방식 : KIS 증권사 알고리즘 위임을 전면 소각하고, 매 1분마다 산출된 할당 수량을 1호가 지정가(LIMIT)로 직접 쪼개어(Slicing) 전송.
▫️ 15:27~15:55 (페이스 조절) : 누적 가중치에 따라 정밀 분할 타격 유지.
▫️ 15:56 (마지막 틱 정량제 캡핑 및 스윕) : 누적 가중치 1.0 도달 시, 예산을 억지로 100% 소진하거나 1회분을 초과하는 보유 물량을 전량 매도해버리는 과거의 정액제 풀-스윕 맹독성 로직을 시스템 전역에서 전면 소각하라. 오직 스냅샷에 락온된 **'당일 잔여 목표 수량(Remaining Target Qty)'**만을 실시간 1호가로 스윕(Sweep) 타격하여 1회분(Portion) 정량제 원칙을 완벽히 관철한다.
🔸 무덤핑 및 정밀 요격 (수동 덫 소각) : 목표가를 충족시키기 위해 가격을 강제 훼손하는 막판 덤핑(슬리피지 허용) 영구 소각. 매수/매도 1호가가 목표 타점을 충족할 때만 100% 즉시 타격하며, 미충족 시 1주도 사지 않고 철저한 관망세 유지.

🚨 Case 41 하방 하이재킹 큐 장부 절대 락온 (V-REV 전용) : 하이재킹 모드(Gap Hijack 등 폭락 변동성 대응)는 오직 V-REV 모드에서만 가동된다. 매도 격발 시 증권사 서버의 실잔고 조회를 전면 소각하라. 오직 로컬 큐(Queue) 장부에 기록된 수량만을 매도 대상으로 100% 락온하여, 봇 관리 외 사용자의 개인 장기 물량 훼손 사고를 완벽히 방어한다. 또한, 큐 장부상 보유 수량이 0주(새출발 상태)일 경우 어떠한 상황에서도 매도(SELL) 로직이 격발되지 않도록 즉시 바이패스(Bypass) 단락 평가를 강제하라.
🚨 Case 42 소프트웨어 트리거 중복 발사(Double Fire) 원천 차단 : 가격 감시 폴링 루프 내에서 돌파가 포착되어 매수 API를 호출하는 순간, 즉시 로컬 메모리에 락(Mutex Flag, 예: is_ordering=True)을 걸어 API 응답이 오기 전까지 다음 루프에서 중복 매수 주문이 격발되어 예수금을 초과 탕진하는 대참사를 100% 방어하라.

🚨 Case 44 KIS 유령 잔고(Ghost Balance) 졸업 차단 : API 통신 오류로 KIS 실잔고가 0주로 응답되더라도, 당일 매도 체결 내역(SELL)이 0건인데 로컬 큐(Queue) 장부에 물량이 존재한다면 즉시 졸업(장부 소각)을 강제 차단하여 데이터 증발 대참사를 방어하라.
🚨 Case 45 암살자 물량 격리 졸업(Decoupled Graduation) : 본진(V-REV)의 조기/정규 졸업(0주) 달성 여부를 판별할 때, KIS 총 실잔고에서 반드시 '암살자 독립 장부(AssassinLedger)의 보유 수량'을 차감한 순수 본진 물량(pure_vrev_qty)으로 계산하라. 암살자가 물량을 들고 오버나이트 중이더라도 본진의 0주 새출발이 마비되지 않아야 한다.

🚨 Case 47 전역 파일 뮤텍스(File Mutex) 강제 락온 : 설정 파일(config), 큐 장부, 상태 캐시, 스냅샷 등 모든 로컬 파일의 읽기/쓰기 작업 시, 인스턴스 전역 락(self._io_lock 등)을 전면 금지한다. 반드시 파일 경로를 식별자로 하는 GlobalThrottle.get_file_lock(filepath) 컨텍스트 매니저를 사용하여 다중 비동기 스레드 환경에서의 데이터 증발(Lost Update) 및 더티 리드(Dirty Read)를 물리적으로 원천 봉쇄하라.
🚨 Case 48 큐 장부 격리 및 2-Tier 병합 강제 : 오리지널 모드(V14 LOC, V14 VWAP)에서는 큐 장부를 절대 호출하거나 적용하지 마라. V-REV 모드에서만 활성화되며, 큐 장부 팽창 시(3개 지층 이상) 반드시 2층과 3층을 통합하는 로직을 거쳐 2-Bucket 체제를 유지해야 한다.
🚨 Case 49 스레드 풀 고갈(Thread Pool Exhaustion) 및 락 내부 블로킹 금지 : 락(Lock)을 획득한 상태에서 time.sleep()이나 네트워크 I/O 등 블로킹 연산을 수행하여 파이썬 백그라운드 스레드 풀 전체를 마비시키는 맹독성 행위를 엄격히 금지한다. TPS 제어(GlobalThrottle) 시 락 내부에서는 미래 실행 슬롯(시간)만 예약하고 즉시 락을 해제한 뒤, 락 외부에서 대기하는 '논블로킹 토큰 버킷(Non-blocking Token Bucket)' 아키텍처를 강제하여 이벤트 루프 교착을 원천 봉쇄하라.
🚨 Case 50 전역 락(tx_lock) 데드락 방어 및 임계 구역 최소화 : 스나이퍼(scheduler_sniper.py) 등 빈번하게 폴링하는 스케줄러 전체를 async with tx_lock:으로 감싸서 타 스케줄러(VWAP 엔진 등)와 경합하여 55초 타임아웃 붕괴를 유발하는 설계를 영구 소각하라. 전역 락은 오직 주문 실행 및 장부/상태 변경이 발생하는 최소한의 임계 구역(Critical Section)에만 국소적으로 팩트 적용하여 병렬 처리 성능을 극대화하라.
🚨 Case 51 동시 기상 병목(Thundering Herd) 및 사일런트 바이패스 차단 : 다중 스케줄러가 동시에 기상할 때 발생하는 달력 API(mcal) 무한 중복 스캔 병목을 막기 위해 반드시 전역 인메모리 캐싱(_MCAL_CACHE) 파이프라인을 100% 락온하라. 또한, 지시서 갱신 누락이나 I/O 에러로 인해 슬라이싱 엔진이 조용히 침묵(Bypass)할 경우, 관제탑에 즉각 에러를 타전하고 텔레그램 수동 타격을 권고하도록 알림 방어막을 결속하라.
🚨 Case 52 1회분 수동 제어망 팻핑거 및 오염 방어 : 1회분 수동 매수/매도(MANUAL_PORTION) 기능은 오직 V-REV 모드에서만 작동하도록 100% 격리하여 V14 모드 오염(팻핑거)을 원천 차단하라. 격발 시 가용 현금/큐 장부 잔량에 따른 동적 내림 캡핑(Capping)을 적용해 서버 리젝을 방어하고, 수동 타격 직후 큐 장부에 원자적 업데이트를 강행하여 3개 지층 이상 발생 시 2층과 3층을 즉각 자동 병합(Auto-Merge)하여 아키텍처 무결성을 유지하라.
🚨 Case 53 풍선 효과(Balloon Effect) 단가 폭등 하드 캡핑 : 지층 분할(Split) 또는 상향식 이관(Top-Down Push) 시, 1층을 저가(당일 체결가)로 떼어내면서 남은 투자금이 상위층으로 쏠려 상위층의 단가가 '기존 총 평단가'를 초과하여 폭등하는 패러독스를 원천 차단한다. 산출되는 상위층 단가(rem_price)는 반드시 기존 전체 총 평단가를 상한선으로 강제 캡핑(Hard Capping)하라.
🚨 Case 54 상태 파일 스키마 불일치(Target Price Amnesia) 방어 : 플랜 생성 시에는 'price' 키를 쓰지만 로컬 슬라이싱 지시서(slice_state)에는 'target_price'로 저장되는 스키마 파편화가 존재한다. 값을 추출할 때 반드시 _safe_float(o.get('target_price', o.get('price', 0.0)))의 듀얼 폴백으로 추출하라. 단가가 0.0으로 인식되면 가격 검증망이 뚫려 매수/매도가 동시에 무지성 격발되는 자전거래 및 손실 덤핑 대참사가 발생한다.
🚨 Case 55 무지성 풀-스윕(Full-Sweep) 덤핑 절대 금지 : 15:56 마지막 틱(가중치 1.0) 도달 시, 예산을 억지로 100% 소진하거나 1회분을 초과하는 보유 물량을 전량 매도해버리는 과거의 맹독성 로직을 절대 복구하지 마라. 오직 스냅샷에 락온된 '당일 잔여 목표 수량(Remaining Target Qty)'만을 실시간 1호가로 스윕(Sweep) 타격하여 1회분(Portion) 정량제 원칙을 완벽히 관철하라.
🚨 Case 56 하이재킹 타점 오염 방어막 (Price Over-Hijack Shield) 결속 : 하방 갭 하이재킹(Gap Hijack) 격발 시, 당일 스냅샷에 앵커링된 최고 매수 단가보다 실시간 현재가가 더 높은 상태에서 스윕 매수가 발생하면 퀀트의 'Buy Low' 원칙이 훼손된다. 하이재킹 발동 직전, 반드시 현재가와 지시서 내 매수 목표가를 교차 검증하여, 현재가가 더 비쌀 경우 무조건 하이재킹 매수를 스킵(Bypass)하고 관망세를 유지하는 로직을 하드코딩하라.
🚨 Case 57 이중 타격(Double Spending) 및 기억 상실(Amnesia) 붕괴 궁극 수술 : 슬라이싱 중 KIS 서버 API 타임아웃(Timeout)이나 랙(Lag)으로 체결 원장을 조회하지 못했을 때, 메모리에 저장된 주문번호(last_odno)를 강제 삭제(Amnesia)해버려 방금 샀던 수량을 다시 사버리는 '오버슈팅(Overbuying)' 패러독스를 완벽히 도려내라. 원장 조회 실패 시 주문 번호를 유지한 채 안전하게 다음 1분 틱으로 검증을 이연(Delay)시켜야 한다.
🚨 Case 58 지층 독립성 절대 락온 (Type Check Enforcement) 및 팽창 방어 : add_lot 및 sync_with_broker 로직에서 동일 날짜(today_str)라는 이유만으로 분할 마법 지층(AUTO_SPLIT_L1)과 정규 매수 지층(VREV_VWAP_BUY)이 무지성으로 병합되어 1회분 정량을 초과(팽창)해버리는 대참사를 원천 봉쇄하라. 날짜뿐만 아니라 지층의 기원(lot_type)이 100% 일치할 때만 병합되도록 엄격한 타입 필터망을 체결하라.
🚨 Case 59 당일 복합 타격 지층 단일화 (lot_type 일원화) : 1분 슬라이싱(VWAP), 수동 1회분 매수(MANUAL_PORTION), 하방 하이재킹 스윕(Gap Hijack), 애프터장 지연 매수 등 당일 발생한 모든 V-REV 본진의 매수 타격은 큐 장부 기록 시 기원 식별자를 반드시 "VREV_VWAP_BUY" 하나로 100% 일원화(통일)하라. 식별자가 파편화될 경우 동일 날짜임에도 지층이 분리되어 1층에 2회분이 중복 저장되거나 불필요한 지층 팽창 패러독스가 발생한다.
🚨 Case 60 단일 지층 팽창 패러독스 (Parameter Amnesia) 원천 봉쇄 : 매도 체결 후 큐 장부를 차감(pop_lots)할 때, 1회분 초과 지층의 정밀 분할(Tier Split)에 필수적인 prev_close와 portion_budget 파라미터가 유실되지 않도록 하라. 정규장 슬라이싱, 애프터장, 수동 긴급 수혈 등 모든 매도 격발 엔진에서 타격 직전 실시간으로 팩트를 추출하여 100% 무결성으로 주입해야 한다.
🚨 Case 61 전역 스코프 붕괴(NameError) 절대 방어 : 클래스 외부의 전역 함수(Global Function)에서 self. 키워드를 호출하여 런타임 즉사(NameError)가 발생하는 대참사를 원천 차단하라. 유틸리티 함수(_safe_float 등) 호출 시 현재 스코프가 클래스 내부인지 전역인지 반드시 교차 검증하고, 전역 스코프에서는 self. 접두사를 영구 소각하여 다이렉트로 호출하라.

🚨 단일 파일 격리 수술 3단계 프로토콜
🔸 1단계 (로그 진단) : 사용자가 에러 로그만 제공하면, 21개 파일 중 어느 파일/함수에서 발생한 문제인지 타겟만 식별하여 브리핑하라.
🔸 2단계 (논리 승인) : 사용자가 타겟 파일 코드를 주입하면, 에러 원인과 해결 논리만 설명하고 절대 코드를 먼저 짜지 마라.
🔸 3단계 (전체 코드 출력) : 사용자가 "수정해", "코드 출력해" 등 명시적 승인 트리거를 발동하면, 합의된 로직을 적용하여 해당 파일의 100% 풀 코드를 생략 없이 출력하라.
🚨 원샷 딥다이브 교차 검증 (One-Shot 기법) 프로토콜
사용자가 "재검증" 또는 "오류 확인"을 요구할 경우, 불필요한 질의응답 핑퐁을 전면 폐기하고 즉시 아래 3중 타격망을 내부 연산으로 가동하라.
🔸 1차 타격 (Syntax & Async I/O 붕괴 검사) : 코드를 출력하기 전 파이썬 컴파일러의 관점에서 완벽한가? 들여쓰기(Indentation) 불일치, try 블록 하위의 except/finally 누락, 괄호 불일치 등 런타임 즉사 에러(SyntaxError)를 최우선으로 100% 검증하라. 또한 requests, json.load 등 단 하나의 동기 함수라도 asyncio 이벤트 루프를 블로킹하고 있지 않은가? KIS 서버 Rate Limit (TPS 20) 방어용 강제 지연(sleep)이 누락된 루프가 존재하는가?
🔸 2차 타격 (State Mismatch & 멱등성 검사) : 로컬 장부(JSON) 기록과 KIS 실서버 잔고 간의 동기화가 끊어질 수 있는 논리적 틈새가 있는가? 에러 발생 시 재시도(Retry) 과정에서 변수가 오염되지 않고 멱등성이 유지되는가?
🔸 3차 타격 (Quant Logic & Float 정밀도 검사) : 분모가 0이 되는 상황(ZeroDivision), T값 및 별값 계산 시 Float 연산 오차로 인한 슬리피지 발생 가능성, 타점 역전 현상이 존재하는가?
🔸 통합 및 강제 렌더링 (일괄 타결) : 위 3단계 타격에서 발견된 모든 취약점(특히 들여쓰기 및 문법 오류)을 내부 메모리에서 즉시 보완(수정 승인 간주)하라. 그 후 '무엇이 문제였고 어떻게 방어 코드를 주입했는지' 5줄 이내의 이모지 핵심 요약 브리핑을 최상단에 타전하고, 직후 합의된 100% 풀 코드를 단일 코드 블록으로 생략 없이 렌더링하라. (중간 보고 및 승인 대기 절대 금지)
